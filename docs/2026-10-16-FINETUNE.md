# M1 verified-example fine-tune and development comparison

Date: 2026-10-16, Australia/Sydney.

The short fine-tune improved stopping, brevity, and some factual recall. It still
fails most development tasks, including the held-out-source questions, debugging,
and code generation. Retain it as an experimental checkpoint; these results do
not justify replacing the default model.

## Training

Executed in `/Users/jq/qos_ai_eval` on `JQs-Mac-mini.local` (Apple M1, 16 GiB),
through Tailscale SSH as `jq`. No cloud resources were used.

- Parent: `qos_ai/pod_pt15/student.pt`, the existing 168M student.
- Training data: exactly the 65 prepared, source-verified training examples.
- Five epochs, 325 example presentations, 85 optimizer steps, approximately
  **104 seconds**. The ten-minute budget guard was not reached.
- Answer-only supervised cross-entropy, including the end-of-answer token.
  Questions and padding were excluded from the loss. No teacher was loaded.
- Learning rate 0.00005, AdamW with weight decay 0.01, five warmup steps, cosine
  decay, gradient clipping 1.0, microbatch two, gradient accumulation two, seed 7.
- Model architecture and vocabulary unchanged. One unknown answer token per pass
  was skipped: 10,210 known supervised tokens were learned across five passes.
- Training-set loss: **3.036 → 0.034**. This demonstrates strong fitting to the
  small curriculum, not generalization by itself.

## Correctness evidence and scoring limits

Lexical rubric matching is **not factual accuracy**. Inspection found both false
positives (a correct number echoed inside code while the stated output was wrong)
and false negatives (a correct core fact missing a required qualifier).

The output-literal diagnostic was added after observing this weakness. It strips
code blocks and compares explicitly stated printed values with the reference
output, rejecting conflicting statements as ambiguous. It is a narrower automatic
diagnostic, not a complete factual or executable-code assessment. The frozen
prompts, model runs and training data were not changed for this analysis.

A separate Codex source review assessed the same **12 preselected development
questions** used in the earlier diagnostic, for both unguarded runs:

- Parent: **0/12 correct**.
- Fine-tuned: **2/12 correct core answers**, with omitted qualifiers noted.
- Review coverage: 12/90 for each model. This was agent source review, not
  independent human review, and is not an estimate of accuracy on all 90 prompts.
- Judgments record answer hashes, reviewer identity, source locations and reasons.
  Generated model code was not executed; compilation/behavior metrics remain unset.

The two improved sample answers concerned the compiler commit recorded by
`qos.py fprisc --pin` and rejection of JSON input followed by extra text. Broader
inspection also found correct recall of `fpr build`, actor `send` results and
JSON duplicate-key handling.

Important remaining failures:

- Held-out-source track: **0/15 rubric matches** after fine-tuning, with or without
  the repetition guard. Parent scores were 1/15 raw and 2/15 guarded; review showed
  proxy false positives, so these are not evidence of a corresponding factual
  regression. All fine-tuned proxy gains were on familiar-concept material.
- Debugging: **0/2** rubric matches. Code generation: **0/2**.
- Output prediction is still mostly wrong. For example, the model says
  `Numeric.clamp 0 10 15` prints 15, despite copying code whose actual output is 10.
- Some source explanations still invent contracts: out-of-bounds binary reads
  become fabricated Result errors, and the default profile is misidentified.
- Insufficient-information handling did not improve.

These results support increasing the diversity and coverage of the verified
curriculum. The very low training loss suggests the existing 65 examples are
already strongly fitted; reliable transfer to reworded questions and new inputs
remains the main problem.

## Implementation checks and provenance

**38 regression tests passed on the M1**: existing split/benchmark tests, answer-only
training/masking/input-validation tests, checkpoint portability, and paired
comparison/output-diagnostic checks.

The initial checkpoint save exposed a metadata portability bug: PyTorch's version
was stored as a `TorchVersion` object, which the ordinary restricted loader
rejects. The writer now stores plain metadata and verifies `weights_only=True`
loading before publishing a checkpoint. Tied embedding/head storage is preserved.

The already-trained checkpoint was repaired without retraining. Model-state hashes
before and after repair were both:
`77896446c4cdb8351266f8755f9e238af5fe52f95c133c084462db884e6bbb53`.
The original-format artifact, original training script and repair script were
preserved on the M1. All fine-tuned comparison runs used the repaired checkpoint.

The split manifest remains:
`cd57f4a7b5c2b02b40c6b8679c39a82712535c33254385a9139cfe8504529be3`.
Both models retain `legacy_or_unknown` prior-exposure ancestry; the new split
cannot retroactively certify the parent's training history. This was one seed
and one short run, with no general-English or hardware-target capability audit.
