## 4. Expand verified instruction training

Target roughly 10,000-20,000 diverse examples as an initial preparation goal. This range is a proposed experiment size, not a demonstrated requirement. Prioritize distinct operations, program structures and compositions rather than many numerical variants of a few templates.

Balance these objectives:

- Generate complete programs that use exactly the supplied inputs.
- Calculate outputs and verify intermediate values as well as final literals.
- Provide complete repairs, including corrected code and the resulting output.
- Recognize already-correct programs and avoid unnecessary edits.
- Explain APIs and compiler diagnostics from pinned source evidence.
- Give concise factual answers and identify insufficient information or false premises.

Execute every self-contained code target against its intended compiler and inputs. Verify calculation explanations and input-contrast pairs, not just whether the final output appears somewhere in an answer. Reject unsupported claims and record source, verification and split provenance. Audit full-example encoding, end-of-answer tokens and length coverage before choosing padding; never silently truncate the answer to fit the pilot's 192-token SFT width.

Reserve entire program/task families for validation before generating related variants. Keep the original development and reserved test material excluded from training. Teacher-generated material can be used as candidate teaching data only after these checks; it does not change the model's random-weight initialization lineage.
