# Fresh Sol question probe

Date: 2026-10-20. 32 new questions, written for this probe and screened against every training and benchmark
question (the one exact duplicate and one verbatim training program were replaced before running). Code answers
were computed with the local `fpr` compiler; generated programs were executed. Greedy decoding, no repeat guard,
200 new tokens, on the M1. Files: `qos_ai/probe_sol_20261020/` (questions, scorer, raw answers).

What the answers show:
- Output questions get a confident short number that is usually wrong (e.g. `List.sum (List.map (fn x -> x * 5) [2, 7, 4])`
  → 6, 42, 25, 36; correct 65). Several "hits" are coincidences: the mixed model answered "It prints 10." to four
  different questions.
- Generation copies the training template: every model wraps "keep the numbers greater than 5" in `List.sum` and uses
  `>= 5`. Doubling-and-summing works (3 of 4 models) because it is exactly the trained template.
- Unfamiliar questions trigger memorized answers: "Run `./fpr sol path/to/script.sol`..." and "The Sol JSON parser
  validates the whole document..." appear as answers to unrelated questions.
- The 557M with mixed SFT is the only model that recalls real documentation in new wording (Proc.afterCommit → redo
  journal, at-least-once; Proc.query → read-only, safely retried), but it mixes those facts with invented details.

These four pre-Stage-3 models performed poorly on this small fresh-question probe, with frequent template copying
and arithmetic errors. Their earlier benchmark gains did not transfer reliably to these questions. The mixed
557M model showed some documentation recall, accompanied by unsupported details. This probe alone does not
establish the cause of every benchmark gain or rule out all generalization.
