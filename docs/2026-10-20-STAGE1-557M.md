# Stage 1: domain training for the 557M, with a matched 168M control

Date: 2026-10-20 (Australia/Sydney; GPU run 2026-10-19 12:59-13:52 UTC). Status: training, backup and
the main M1 evaluations complete; all pods terminated. Code and plan: [runpod/stage1/](2026-10-21-RUNPOD-STAGE1.md).

## Question and setup

The 557M pilot never saw fprisc/qos text before its 2,784-example SFT, so its weak factual scores could
not say anything about model size. Stage 1 gave it, and a 168M control, the same domain stage and the
same SFT:

| | 557M | 168M control |
|---|---|---|
| Parent | pilot `pretrained.pt` (459M tokens, 80% English / 20% Python, random init) | `qos_ai/pod_pt/pretrained.pt` (500M FineWeb tokens, Qwen 0.8B embedding init) |
| Domain stage | 7,592 updates, 62M tokens: training-partition docs + 107,364 4B Q&A pairs (2 passes, answer-only loss on Q&A), 25% English/Python replay, lr 1e-4 | identical |
| SFT | pilot treatment: 2 epochs over the 2,784 verified examples, lr 5e-5, 174 updates | identical |
| Throughput (RTX 4090) | 27.9k tok/s | 74.2k tok/s |

The parents still differ in initialization and data mix, so this narrows but does not isolate the size
effect. Only training-partition material was trained on; the dev partition is used only for probes and the
benchmarks; the test partition was not used.

## Findings

1. **Under the same recipe, the 557M learns the domain better than the 168M.** Held-out doc perplexity is
   19% lower (23.8 vs 29.3) and held-out Q&A answer perplexity 11% lower (9.92 vs 11.2), although the
   557M starts behind on English and had no embedding head start. After SFT it scores 34/90 dev lexical
   matches against 15/90, and is ahead or level on 9 of the 10 benchmark columns. This is the first
   evidence in this project that size helps; it is one seed per model.
2. **The domain stage is what the pilot was missing.** Same 557M, same SFT: dev lexical 9 → 34, applied
   repairs 23 → 29, working programs 17 → 18.
3. **The pilot's SFT treatment is too aggressive.** It undoes a large share of the domain stage on held-out
   text (557M docs 23.8 → 37.9, Q&A 9.92 → 17.8) and costs more English. SFT loss ends at 0.18 on 2,784
   templated examples. A lower learning rate, one epoch, or mixing domain Q&A into SFT should keep more.
4. **25% replay did not prevent English forgetting.** FineWeb English rose from 32.9 to 47.8 (557M) and
   from 27.1 to 46.5 (168M) during the domain stage. Far better than the old 168M distillation (over
   1,300), but still a large loss. More replay or a lower learning rate is needed if general English matters.
5. **The chained 168M models still lead on narrow coding and dev lexical scores.** They have seen far
   more targeted curriculum (five SFT rounds, about 4,800 verified examples, plus the 4B distillation). The
   stage-1 models had only the 2,784-example SFT. Matching that curriculum is the next comparison.
6. **The no-repeat guard keeps costing coding and trace scores for every model** (557M: working programs
   18 → 14, strict trace 24 → 10). Report raw decoding alongside guarded from now on.

## Suggested next steps

1. Re-run only the SFT from the two `domain.pt` checkpoints with a gentler treatment (for example one epoch
   at 2e-5, with 50% domain Q&A replay). A few minutes of GPU per model, or a long M1 run for the 168M.
2. Give the 557M the same verified curriculum the chained 168M saw, in one mixed SFT, and compare against
   the 168M coding parent.
3. Raise English replay (for example 50%) or lower the domain learning rate if general English matters.
4. Continued pretraining of the 557M towards 1B tokens remains the larger lever (about $5.30 per extra
   550M tokens) now that the domain stage is shown to transfer.
