## 1. Hybrid retrieval (no GPU)

Qwen3-Embedding-0.6B vectors for all 1,820 corpus chunks, fused with BM25 by reciprocal rank, on the same 300
held-out dev questions ([data](data/qos_ai_benchmark/qwen_round2_20261022/hybrid_retrieval.json)):

| Source file found in | Top 1 | Top 3 | Top 5 |
|---|---:|---:|---:|
| BM25 | **56.3%** | 74.0% | **81.3%** |
| Dense (Qwen3-Embedding-0.6B) | 49.0% | 61.3% | 66.0% |
| Hybrid (reciprocal rank) | 55.0% | **75.7%** | **81.3%** |

The dense model is worse than BM25 here: questions name exact identifiers (`FPR_PATH`, `std/binary`) that keyword
matching finds directly. Hybrid search adds nothing meaningful, so BM25 stays the default; `--embeddings` is
available in `rag-loss`, `ask` and `answer` for later experiments.

## 2. Round-2 data

**Tasks** (`qos round2 tasks`, new seeds; excludes the frozen tests, all training programs, the Stage 4/5 expression
sets and the earlier self-sampling tasks): 4,201 compiler-checked tasks, namely 1,542 predict-the-output, 910 write,
548 repair, 455 expressions and 746 conditional expressions whose two branches must give different results on the six
test inputs ([report](data/qos_ai_benchmark/qwen_round2_20261022/tasks_report.json)).

**Sampling** with the fine-tuned Qwen (seed 7) on the Macs: greedy for program tasks, four samples at temperature 0.8
for expressions. Judged with the pinned compiler ([report](data/qos_ai_benchmark/qwen_round2_20261022/rows_report.json)):

| Task | Solved | Correct samples |
|---|---:|---:|
| Predict the output | 1,321 / 1,542 (86%) | greedy |
| Write a program | 788 / 910 (87%) | greedy |
| Repair | 467 / 548 (85%) | greedy |
| Expressions | 448 / 455 | 1,416 / 1,820 (78%) |
| Conditional expressions | 701 / 746 | 1,852 / 2,984 (62%) |

Program tasks have one right answer that the generator already knows with an exact trace, so failures keep the
reference answer (424) plus a quarter of the successes (617, to avoid narrowing the distribution). Expression tasks
keep up to two distinct confirmed samples of the model's own (2,188), or the reference when none passed (52).

**Long-reference retrieval examples** (`qos round2 rag`): 3,000 training-partition questions not used in Stage 5, each
with 1-3 BM25 chunks from training-partition files cut to 1,500 tokens (mean 3,450 characters per prompt).

**Merge**: 89,314 examples; the 6,281 additions are 606k target tokens on top of Stage 5's 4.89M (+12%); none skipped.

## 3. Training run

Same recipe as seeds 7 and 17 (seed 7, lr 1e-5, 32 examples per update, one pass; 2,792 updates).

- **First attempt ran out of GPU memory after 48 minutes** (about $0.75 lost). Each update's examples had been
  regrouped by length, and four ~1,800-token retrieval examples landed in one micro-batch; the 248k-word output
  layer at their answer positions and allocator fragmentation did the rest.
- **Fix**: `micro_batches` splits each update's examples by a token budget (2,048 padded tokens, 1,024 answer tokens;
  never more memory than Stage 5's 4 x 512), and `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`. The update is
  unchanged (same examples, summed loss). Short examples now pack 8-13 per micro-batch: **6,330 tokens/s versus
  3,560**, GPU 99% busy, 20.4 of 24.5 GB. Training took 35 minutes.

## Assessment

- **Sol behaviour is unchanged.** Every Sol measure is inside the spread between seeds 7 and 17. Training on the
  model's failures (424 references) and its own confirmed expressions did not move stated outputs or the conditional
  family. At 86-87% solved on fresh tasks, there is little left for these task types to teach in one pass.
- **Using references improved clearly.** With references in the prompt, round 2 answers 28 of 51 development
  questions against seed 7's 19, and its retrieval perplexity is about 4% lower.
- **Closed-book recall got worse.** Without references, development Q&A fell from 41-42 to 32, including the code
  questions that `ask` never gives references (31 → 25). Learning to answer from a reference seems to weaken
  answering from memory.
- Overall, round 2 suits a retrieval-backed assistant; seed 7 is better without retrieval. Neither is a default.

## Next

1. **Keep closed-book recall**: pair each retrieval example with the same question and no reference (or replay the
   Stage 5 Q&A at a higher share), and try giving the 39 code-type development questions references too.
2. **Qwen3.5-2B, efficiently** (measured inputs for the estimate):
   - token-budget packing gave 1.8x on the 4090; with 96 GB the budget can rise to about 8,192 tokens;
   - compute per token is roughly 2.5-3x the 0.8B (hidden size 2,048 vs 1,024, same 24 layers; the tied 248k-word
     embedding is computed only at answer positions);
   - on an RTX PRO 6000 ($2.49/hr, the only 48 GB+ GPU in EU-RO-1) that is about 40-55 minutes of training, about
     $2.00-2.50 including setup and evaluation; a 90-minute cap bounds it at $3.75;
   - base-model answers generated free on the M1 instead of on the pod; weights pulled to the M1 as before;
   - stop within 10 minutes if the measured speed projects past the cap.
3. Dense retrieval is not worth pursuing with this embedder; better gains are likely from chunking by section and
   from the closed-book fix above.
